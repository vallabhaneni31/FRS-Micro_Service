# FRS — service & contract index

> Estate-level retrieval index. When a change crosses the frontend/backend boundary, this is
> where the agent learns the other side of the contract without cloning and grepping the peer
> repo. Generated by `/ml-specs:repo-estate`. Two repos in this estate; peers are siblings under
> `Micro-Service/`, not a monorepo — `backend/api-retail` and `backend/api-transport` are
> internal to `frs-core-api` (see its `docs/ARCHITECTURE.md`), not estate peers.

## Service registry

| Service | Owns | Stack | Summary doc |
|---|---|---|---|
| `frs-core-api` (this repo) | Backend: auth, attendance, device mgmt, enrollment, reporting, retail, transport verticals | Node/Express (`backend/api`, `backend/api-retail`) + Java/Spring (`backend/api-transport`) | `docs/ARCHITECTURE.md` |

## How to use this for retrieval

1. Read this repo's own `docs/ARCHITECTURE.md` (or `frs-web-ui/docs/ARCHITECTURE.md`) first.
2. Only if the task touches a route, the websocket contract, or the manifest shape: find the edge
   above, then open the peer's summary doc — design against both sides, note deploy order in the
   spec's §7 Rollout.
3. Then agentic search for exact lines. Several rows above are `_TBD_` — resolve the specific one
   your task touches rather than trusting a guess.
