## What it is
FRS core API — Motivity Face Recognition System's backend. Three independently deployable
services live under `backend/`, on two different stacks (see `docs/PATTERNS.md` for per-service
conventions). Only `backend/api/**` is built/deployed by this repo's CI (`azure-pipelines.yml:44-49`);
`backend/api-retail` and `backend/api-transport` are excluded and moving to their own repos
(`azure-pipelines.yml:8-11`). The `frontend/` this repo's README still describes does not exist
here — see "Known drift" below.

## Structure (where to look by feature)

| Service | Path | Stack | One-liner |
|---|---|---|---|
| Core API | `backend/api/` | Node/Express, raw `pg` | Auth, attendance, device management, reporting, enrollment — the primary service |
| Retail API | `backend/api-retail/` | Node/Express, raw `pg` | Standalone retail vertical (people counting, occupancy, analytics) |
| Transport API | `backend/api-transport/` | Java/Spring Boot 3 + JPA/Flyway | Separate "transport" vertical, different customers, different stack |

## Data & persistence
- **Engine:** PostgreSQL for both Node services (`backend/api`, `backend/api-retail`), each with
  its own pool (`backend/api/src/db/pool.js`, and a second `retailPool` also reachable from
  `backend/api` — `backend/api/src/routes/authRoutes.js:34-35`).
- **Access layer:** no ORM in the Node services — hand-written parameterized SQL via `pg`.
  `backend/api-transport` (Java) uses Spring Data JPA instead — do not conflate the two data-access
  styles; see `docs/PATTERNS.md` for both.
- **Migrations:** `backend/api` — flat numbered SQL files in `backend/api/src/db/migrations/`,
  applied via `backend/api/scripts/migrate.js` and one-off `run_migration_NNN.js` scripts (not an
  npm script). `backend/api-transport` — Flyway (`backend/api-transport/pom.xml:42-56`).
- **Tenant isolation:** two models coexist mid-migration (RLS via `app.tenant_id` session var, and
  legacy `frs_tenant_user_map` joins) — detailed in `docs/architecture/BACKEND_ARCHITECTURE_OVERVIEW.md:8`.

## Cross-cutting
- **Errors:** `backend/api` has one central Express error middleware (`backend/api/src/server.js:631-649`);
  no typed error class exists — see the "Don'ts" in `docs/PATTERNS.md`.
- **Auth:** dual-mode in `backend/api` — legacy opaque tokens and Keycloak JWT both supported at
  the bootstrap endpoint (`backend/api/src/routes/authRoutes.js:322-492`). `backend/api-transport`
  uses Spring Security + JJWT, explicitly not the OAuth2 resource-server starter (`backend/api-transport/pom.xml:60-61`).
- **Config:** per-service `.env` files (see root `README.md`'s Configuration table — accurate for
  this section as far as scanned).
- **Quality gates:** `backend/api` — `npm test` locally, but CI's real gate is narrower
  (`node --test src/tests/password.test.js src/tests/security.test.js`, `azure-pipelines.yml:96-99`).
  No lint/typecheck configured for `backend/api`. See `docs/PATTERNS.md` for the full breakdown
  per service, including `backend/api-transport`'s Maven/JUnit path.
