## The 10-Step Bug-Fix Process

### 0. Stale Check — Before Touching Code
Check whether the reported defect was already resolved in a later commit:
```bash
git log --all -S"<distinctive string from ticket>" -- <file>
```
If verified stale, post a comment citing the fixing commit and close without opening a branch.

### 1. Triage — Pull the Ticket
```bash
az boards work-item show --id <id> --org https://dev.azure.com/ML-AIML-COE
```
Evaluate actual impact (blocker, core security, data loss, user reach).

### 2. Open & Branch
**2a. Set state to Active:**
```bash
az boards work-item update --id <id> --state Active --org https://dev.azure.com/ML-AIML-COE
```

**2b. Set estimate hours:**
```bash
az boards work-item update --id <id> \
  --fields "Microsoft.VSTS.Scheduling.OriginalEstimate=<hours>" "Microsoft.VSTS.Scheduling.RemainingWork=<hours>" \
  --org https://dev.azure.com/ML-AIML-COE
```

**2c. Checkout `allbugfix` and cut bugfix branch:**
```bash
git checkout allbugfix
git fetch origin allbugfix
git pull --ff-only origin allbugfix
git checkout -b bugfix/<id>/<slug>
```
> [!IMPORTANT]
> **CRITICAL RULE:** Always checkout, edit, and commit on `bugfix/<id>/<slug>` FIRST. Never make changes directly on `allbugfix`.

### 3. Investigate & RCA
Deep code inspection with verified `file:line` citations. Never guess. Check actual database column types, schemas, and live auth parameters.

### 4. Scope Gate
If the fix expands beyond the reported issue, ask before expanding. If approved, spin off a linked Azure Boards task:
```bash
az boards work-item create --title "<title>" --type "Task" \
  --org https://dev.azure.com/ML-AIML-COE --project Motivity-Face_Recognition_System \
  --description "Spun off from AB#<original-id>"
az boards work-item relation add --id <new-id> --relation-type "Related" --target-id <original-id> \
  --org https://dev.azure.com/ML-AIML-COE
```

### 5. Implement & Test
- Minimal fix matching existing conventions in the touched microservice.
- Unit/regression tests mandatory (`node:test` for Node.js, `vitest` for React).
- Commit locally referencing `AB#<id>` in commit message:
```bash
git commit -m "fix(service): <summary> (AB#<id>)"
```

### 6. Verify Diff & Direct Tests
- Inspect git diff: `git show <commit> --stat`
- Execute targeted test command directly:
  - Node.js backend: `node --test src/tests/<test-file>.test.js`
  - React frontend: `npx vitest run <path/to/Test>.test.tsx`

### 7. Merge into `allbugfix`
```bash
git checkout allbugfix
git fetch origin allbugfix
git merge --no-ff bugfix/<id>/<slug> -m "Merge branch 'bugfix/<id>/<slug>' into allbugfix

AB#<id>"
```
Re-run the touched service tests on the merged tree.

### 8. Ship
```bash
git push origin bugfix/<id>/<slug>
git push origin allbugfix
```

### 9. Record on Azure Boards
**9a. Link git branch:**
```bash
curl -s -u ":$AZURE_DEVOPS_EXT_PAT" -X PATCH \
  "https://dev.azure.com/ML-AIML-COE/Motivity-Face_Recognition_System/_apis/wit/workitems/<id>?api-version=7.1" \
  -H "Content-Type: application/json-patch+json" \
  -d '[{"op":"add","path":"/relations/-","value":{"rel":"ArtifactLink","url":"vstfs:///Git/Ref/.../GBbugfix%2F<id>%2F<slug>","attributes":{"name":"Branch"}}}]'
```

**9b. Upload verification log/screenshot:**
```bash
attachmentUrl=$(curl -s -u ":$AZURE_DEVOPS_EXT_PAT" -X POST \
  "https://dev.azure.com/ML-AIML-COE/Motivity-Face_Recognition_System/_apis/wit/attachments?fileName=test_results.log&api-version=7.1" \
  -H "Content-Type: application/octet-stream" --data-binary "@test_results.log" | jq -r .url)

curl -s -u ":$AZURE_DEVOPS_EXT_PAT" -X PATCH \
  "https://dev.azure.com/ML-AIML-COE/Motivity-Face_Recognition_System/_apis/wit/workitems/<id>?api-version=7.1" \
  -H "Content-Type: application/json-patch+json" \
  -d "[{\"op\":\"add\",\"path\":\"/relations/-\",\"value\":{\"rel\":\"AttachedFile\",\"url\":\"$attachmentUrl\",\"attributes\":{\"comment\":\"Verification log\"}}}]"
```

Once confirmed:
```bash

```
